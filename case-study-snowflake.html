The challenge

The existing estate combined Oracle, Informatica PowerCenter and Control-M. It worked, but it was costly to operate: 412 tables, 431 mappings, 396 workflows and 94 scheduled jobs required frequent intervention after overnight failures and manual file handling.

The difficult part was not moving table data. Informatica mappings are metadata graphs with execution order and, in some cases, row-level state. A superficial conversion could generate SQL that compiled and ran while quietly returning different results.

The approach

Kovift built a conversion pipeline that treated each mapping as structured data before generating any Snowflake procedure.

  • Parsed mappings into resolved dataflow graphs: sources, targets, transformations, ports and execution order.
  • Generated ordered Snowflake procedures from those graphs, including explicit handling for stateful transformations.
  • Applied structural validation before running anything in the warehouse.
  • Built a direct source-to-target validation framework comparing row counts, null counts, column checksums and numeric totals.
  • Automated ingestion with SnapLogic while retaining Control-M where its enterprise dependencies still mattered.

The result

The on-premise Oracle and Informatica footprint was retired. Annual run cost fell by 50%, manual intervention dropped by 80%, and query performance improved by 50%. More importantly, the migration had a repeatable data-validation gate: no mapping was signed off until the source and target agreed.

Key takeaway

For complex data migrations, generation is only one part of the job. Parsing the original dataflow correctly and validating the actual output data are what make automation reliable.
